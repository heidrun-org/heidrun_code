## File explorer

The File explorer sidebar section shows the whole folder tree of the Git repository of the selected workspace ([issue #349](https://github.com/heidrun-org/heidrun/issues/349)). It shows the files and the folders that Git ignores only when the developer turns on the option "Ignored files" ([issue #430](https://github.com/heidrun-org/heidrun/issues/430)).

- The File explorer sidebar section changes nothing but one thing: it creates a new empty file or a new empty folder, because the developer asked for it ([issue #349](https://github.com/heidrun-org/heidrun/issues/349)). It has no button to rename, move, delete, or edit a file.
- The header stays at the top of the sidebar section while the rows scroll under it. It holds the title "File explorer" and five buttons that show only an icon, in this order: "New file", "New folder", "Refresh", "Collapse all folders" (the icon `dash-square`), and "More options" (three vertical dots).
- The menu of "More options" has four groups, with a separator line between two groups, and a check mark shows the choice that is on. "Indentation": Small (12 pixels for each level), Medium (20 pixels, the default), Large (28 pixels). "Row height": Compact (24 pixels), Comfortable (30 pixels, the default). "Indent guides": Show (the default), Hide. "Ignored files": Show, Hide (the default). The choices are saved in the settings `filesPanelIndent`, `filesPanelRowHeight`, `filesPanelIndentGuides`, and `filesShowIgnored`. The check box "Ignored files" of the Files window uses the same setting `filesShowIgnored`, because both read the same list of files. When the option changes, the program reads the list of files again.
- The folder tree uses the same list of files as the Files window: the files that Git tracks, the new files, and, only when the option "Ignored files" is on, the files and the folders that Git ignores. Folders come first, then files, in alphabetical order. Each row shows, from the left: one indent guide for each level of depth, a slot for the arrow of a folder, the icon of a folder or of the kind of the file, the name, and for a changed file a colored status letter at the right. A file keeps the slot of the arrow empty, so the names of the files and of the folders of one level line up. The color of the icons is in [sidebars_appearance.md](../../web_styling/sidebars_appearance.md).
- "New file" and "New folder" show a name box inside the tree, as the first child of the target folder, indented as the children of that folder. The target folder is the selected folder, or the folder of the selected file, or the root of the repository when nothing is selected. The developer types only the name, and the name cannot contain the character `/`. The key Enter creates the file or the folder, and the key Escape, or a click outside the name box, cancels. A new file opens in the large Git window. A name that exists already gives an error message, and the name box stays open. The new file or the new folder becomes the selected row.
- Git does not list an empty folder, so the tree remembers the new empty folders that the developer created, until Heidrun Code restarts. At each reading of the tree, including the button "Refresh", the program asks the backend which of these folders still exist on the disk, and forgets the others, for example a folder that the developer removed in the Finder or in a terminal.
- The color of a file, of a folder, and of a row that Git ignores is in [sidebars_appearance.md](../../web_styling/sidebars_appearance.md). The folder `.git` is never listed, with the option on and with the option off, because it holds only the internal data of Git. A folder that Git ignores shows once ([issue #441](https://github.com/heidrun-org/heidrun/issues/441)): Git lists both a folder and an entry inside it when the ignore rule names the entry, for example `.heidrun/` and `.heidrun/config.json`, so the program keeps the folder and drops every entry inside it, and the folder unfolds from the disk.
- A folder that Git ignores unfolds with a click, as any other folder. Git does not list the files of such a folder, so the program reads from the disk only the first level of the folder, the files and the folders directly inside it, when the developer unfolds it. A folder inside it unfolds in the same way. A click on a file inside it opens the file in a file view pane. The button "Refresh", and every other reading of the tree, read again each unfolded folder that Git ignores. When a folder cannot be read, it stays folded and a toast tells the reason. The read keeps the protections of the other reads: a known root, a relative path, no symbolic link, and nothing inside `.git`.
- A new file or a new folder inside a folder that Git ignores shows from the disk at the next reading of that folder, so the tree does not remember it in the list of the new empty folders. When the developer turns the option off while the selected row is inside a folder that Git ignores, the selection is cleared.
- A Git submodule appears as an expandable folder with the grey [VS Code file-submodule icon](https://github.com/microsoft/vscode-codicons/blob/main/src/icons/file-submodule.svg). Folders inside an initialized submodule unfold and fold normally, and a click on a file opens the file in a file view pane. Each submodule uses its own Git ignore rules for the option "Ignored files". "Refresh" reads the submodule contents again, keeping unfolded folders unfolded. An uninitialized submodule remains an empty expandable folder; browsing never initializes a submodule ([issue #761](https://github.com/heidrun-org/heidrun/issues/761)).
- "Collapse all folders" folds every folder. There is no button that unfolds every folder.
- A click on a file or on a folder selects its row. Only one row is selected. The selection belongs to the workspace: each workspace keeps its own selected row, and when the developer comes back to a workspace, its selected row is the one that the developer selected there, with the folders above it unfolded. The selection stays when the developer shows another sidebar section and comes back, and when the Files window closes. The backgrounds of the selected row and of a row under the pointer are in [sidebars_appearance.md](../../web_styling/sidebars_appearance.md). A click on the empty space of the sidebar section, outside every row, selects nothing in the selected workspace only.
- A click on a folder folds or unfolds it. The folds stay when the developer changes the sidebar section.
- A right click on the row of a file or of a folder opens a context menu at the pointer ([issue #383](https://github.com/heidrun-org/heidrun/issues/383), [issue #443](https://github.com/heidrun-org/heidrun/issues/443)). A context menu is a small menu that opens at the pointer. It has three items, in this order, with a separator between the second item and the third item: "Copy absolute path" puts the absolute path of the file or of the folder on the clipboard, and "Copy relative path" puts the path of the file or of the folder on the clipboard, relative to the folder of the workspace, and "Chat about this file" starts a chat about the file ([issue #854](https://github.com/heidrun-org/heidrun_code/issues/854)). The item "Chat about this file" opens a new tab with a coding agent in the selected workspace, and sends the coding agent the first message "Let's chat about <absolute path>". The new tab has the name of the file, and the coding agent is the one of the setting "New tab", or Claude when this setting is a terminal, as for the button "Let's chat about this issue". The item shows on the row of a folder too. After a copy, a toast shows the text that was copied. The key Escape, a click outside the context menu, or a click on an item closes the context menu. The context menu stays inside the window. The default context menu of the web view never shows on a row. A copy and a chat change no file, so the File explorer sidebar section still only reads files.
- A click on a file opens the file in a file view pane, read only, and not in the Files window and not in the large Git window ([issue #714](https://github.com/heidrun-org/heidrun/issues/714)). The rules of the file view pane are in [file_view_pane.md](../workspaces_tabs_and_panes/file_view_pane.md). When no pane can show the file, the Files window, the file viewer, opens the file in a tab, as before ([issue #446](https://github.com/heidrun-org/heidrun/issues/446)), and the developer can edit it there. The shortcut ⌘P and a file name in a terminal keep opening the Files window. A selected row of the tree is still only a selected row: a click on a file selects its row and then opens the file.
- The tree is read again when the repository changes, when the number of changed files changes, and at a click on "Refresh".
- The icon `folder2` of the File explorer sidebar section is the first icon of the sidebar icon bar of the left sidebar, above the Launchers icon. It shows no number.
