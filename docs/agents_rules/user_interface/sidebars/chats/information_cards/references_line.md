# Past chats sidebar section: the references line

- Created: 13 October 2026
- Last updated: 23 October 2026
- Status: Maintained rules for agents and tools
- Related framing: [Project instructions](../../../../../../AGENTS.md)
- Related rules: [Glossary of Heidrun Code](../../../../glossary/index.md), [Data layer access](../../../../data_layer_access.md)
- Related issue: [issue 607](https://github.com/heidrun-org/heidrun/issues/607), [issue 617](https://github.com/heidrun-org/heidrun/issues/617), [issue 808](https://github.com/heidrun-org/heidrun/issues/808)

This file is a part of the rules of the user interface of Heidrun Code. The words are defined in [glossary/index.md](../../../../glossary/index.md).

- The references line has an information card, opened the same way as the information card of the files line: the whole line is the part that gets a background under the pointer, and a click on the line opens the information card. A repository without a remote has no forge to read, so its references line has no information card.
- The information card of the references line has a title with the icon of the forge and the text "Issues and pull requests", then one row for each issue, then one row for each pull request. A row shows an icon (a circle with a dot for an issue, the Git icon for a pull request), the title in medium weight, the name and the state in muted color under it ("Issue #250 · Closed"), and a chevron. While the forge is read, the name stands for the title. A line that does not fit scrolls like the lines of the files card.
- A click on a row opens its details under the row, one row at a time, and a second click on the row closes them. The details copy the layout of the card that GitHub shows, from the top: the first line, the title when it is given, the state, a separator, the beginning of the description, the labels or the two branches, a separator, and the person who opened it ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)).
  - The first line shows the repository and the date of the creation ("heidrun-org/heidrun on Oct 11"). The name of the repository is a link that opens the web page of the repository in the web browser, and it is not a link when the address of the repository is not known. The four icon buttons sit at the right of this same line, in one Bootstrap button group.
  - The title is shown only where the row above the card does not show it, as in the card of the Code hosting sidebar section. The whole title shows on as many lines as it needs, never in a scrolling line, and its number follows it in muted color. In the card of this references line, the row above shows the title, so the details have no title.
  - The state is in a pill. The colors of the pill are in [sidebars_appearance.md](../../../../web_styling/sidebars_appearance.md).
  - The beginning of the description is plain text in at most five lines. The labels of an issue show in their colors, as plain pills that do nothing at a click (only the card of the Code hosting sidebar section has labels that change a search, see [code_hosting_search.md](../../code_hosting_search.md)), and the two branches of a pull request show as the receiving branch, an arrow, then the branch with the changes.
  - The last line shows the person who opened it, with the picture of that person. The line says "<login> opened this issue", and it never says "You": the card does not know the account of the developer (on GitHub, the picture at `https://github.com/<login>.png`; on GitLab, the `avatar_url` that GitLab gives). A person without a picture, a login that is not a person (for example `app/dependabot`), and a picture that does not load show the generic icon of a person. "Open in Heidrun Code" (the goat icon of Heidrun Code) opens the description and the comments in the issue window of Heidrun Code, "Open in GitHub" (or "Open in GitLab") opens the web page, and "Copy the GitHub web address" (or "Copy the GitLab web address", the clipboard icon) writes the address of this same web page into the clipboard of the computer ([issue #808](https://github.com/heidrun-org/heidrun/issues/808)). After a click, the copy button shows a check mark for two seconds, with the title "Web address copied"; when the clipboard refuses the address, it shows a cross for two seconds, with the title "Cannot copy the web address: the clipboard refused it.". The copy button is disabled, as "Open in GitHub" is, when the item has no web address. "Let's chat about this issue" (or "Let's chat about this pull request", the icon `chat-dots`) opens a new tab in the selected workspace, starts the coding agent of the setting "New tab" (Claude when this setting is a terminal) in the folder of the workspace, and sends it the first message `Let's chat about <web address>`. The new tab is named after the number, for example "#851". This button is also disabled when the item has no web address ([issue #851](https://github.com/heidrun-org/heidrun_code/issues/851)). While the forge is read, or when it does not answer, the card shows the first line, the title when it is given, one separator, and the text of the wait or of the failure.
- Each time the information card of the references line opens, the program reads every row, four rows at a time. On GitHub, it reads the stored rows with the Tauri command `chat_references_find`, after the Tauri command `chat_references_synchronize` copied the new issues and pull requests of the repository into the SQLite file, with the package `data_layer_code_hosting`, at most once in ten minutes for each folder. A failure of the network does not empty the rows: the stored rows show. On GitLab, the package reads GitHub only, so the program reads the rows live with `glab`, through the Tauri command `forge_cli_cached`, which keeps each answer on the disk, in `forge_cache.json` in the folder of the data of Heidrun Code, for ten minutes: an answer that is at most seven days old replaces a failure. This exception is listed in [data_layer_access.md](../../../../data_layer_access.md).
