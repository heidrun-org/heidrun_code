# Past chats sidebar section: dynamic topics on the rows and the dynamic topic bar

- Created: 13 October 2026
- Last updated: 23 October 2026
- Status: Maintained rules for agents and tools
- Related framing: [Project instructions](../../../../../../AGENTS.md)
- Related rules: [Glossary of Heidrun Code](../../../../glossary/index.md), [Glossary of Heidrun Code: dynamic topics](../../../../glossary/dynamic_topics.md)
- Related issue: [issue 422](https://github.com/heidrun-org/heidrun/issues/422)

This file is a part of the rules of the user interface of Heidrun Code. The words are defined in [glossary/index.md](../../../../glossary/index.md) and [glossary/dynamic_topics.md](../../../../glossary/dynamic_topics.md).

- Under the title of each chat, one single line shows its dynamic topics: at most three small rounded labels (Bootstrap `badge`). The line sits between the title and the summary. A chat without a dynamic topic has no line. While the method is "Language model", a chat shows its line when the language model has given its topics, and shows no line before. The topics come only from the chats that the list shows, never from the other chats of the workspace.
- The dynamic topic bar is the last part of the header, between the line of the two groups and the separator line. It shows the button "All", then one button for each dynamic topic of the chats that the list shows, the strongest first: the topic that more chats have comes first, then the topic that the chats rank higher, then the alphabetical order (`lib/dynamic_topic_bar.ts`). The look of the buttons is in [sidebars_appearance.md](../../../../web_styling/sidebars_appearance.md). The bar has no scroll bar, and it does not scroll by hand or by the wheel. When buttons are hidden after its visible part, an arrow with a fade shows at its end, and each click on the arrow moves the bar so that the next three topics come into view. When buttons are hidden before its visible part, the same arrow shows at its start, and each click goes back by three topics. A button that is partly under an arrow counts as hidden.
- The tooltip (the `title`) of the button of a topic gives the number of chats of the list that have the topic, for example "Show only the chats about “panel” (2 chats)". The number is never written on the button itself, and it stays the same while a topic filters the list.
- Each topic label on the row of a chat is a button (Bootstrap `badge` on a `button`). A click on it does the same as a click on the button of the same topic in the dynamic topic bar: the list shows only the chats that have the topic, the bar marks the topic as selected, and the bar moves to show its button when the arrows hide it. A click on the label of the topic that is already selected shows every chat again, as the button "All" does. The look of the label of the selected topic is in [sidebars_appearance.md](../../../../web_styling/sidebars_appearance.md). The tooltip of a label gives the number of chats of the topic, as the button of the bar does, and the tooltip of the selected label is "Show all the chats".
- A click on a topic of the dynamic topic bar shows only the chats that have the topic, and a click on "All" shows every chat again. The selected topic is not an option and is not saved. The bar forgets it when the developer selects another workspace or another coding agent, and when no chat of the list has the topic any more. The bar is not shown when no chat has a topic, which is the case for the method "Language model" until it has given the first topics.
- While the option "Enable dynamic topics" of the Settings window is off (the option `dynamicTopics`, default on), the Past chats sidebar section shows no dynamic topic bar and no dynamic topic label on the row of any chat, and the list shows every chat. The topic that the developer selected is forgotten. Heidrun Code computes no dynamic topic: the method "Keyword" reads nothing on the forge, the method "Language model" never calls the coding agent `codex` or `claude`, and the clustered dynamic topics make no call. The caches are kept, so switching the option on again shows the topics at once, and the method "Language model" asks only for the chats that have no topic.
