# Past chats sidebar section: the methods of the dynamic topic extraction

- Created: 13 October 2026
- Last updated: 23 October 2026
- Status: Maintained rules for agents and tools
- Related framing: [Project instructions](../../../../../../AGENTS.md)
- Related rules: [Glossary of Heidrun Code](../../../../glossary/index.md), [Glossary of Heidrun Code: dynamic topics](../../../../glossary/dynamic_topics.md)

This file is a part of the rules of the user interface of Heidrun Code. The words are defined in [glossary/index.md](../../../../glossary/index.md) and [glossary/dynamic_topics.md](../../../../glossary/dynamic_topics.md).

- The method "Keyword" reads the dynamic topic source information of each chat: the title, the first messages that the developer typed, the folders of the files that the coding agent wrote (below the root of the repository), and the titles of the issues and of the pull requests that the chat mentioned (the three highest issue numbers and the three highest pull request numbers, read on the forge with `gh` or `glab`, four reads at a time). The messages of the coding agent are not used. It cuts the text into words in lower case, without accents, in the singular, and drops the numbers, the addresses, the words of one or two letters, and the stop words of English and of French (`lib/dynamic_topic_words.ts`). A word of the title counts 3, a word of the title of an issue or of a pull request counts 2, a word of the first messages or of a folder counts 1. The score of a word in a chat is `(1 + ln(weight)) × ln(number of chats that the list shows ÷ number of those chats that hold the word)`, so a word that every chat holds scores nothing. A list of one chat uses only the weight. The best three words, by score and then by alphabetical order, are the topics (`lib/dynamic_topics.ts`).
- The cache of the method "Keyword" is in the `localStorage` of the web frontend, under the key `heidrun.dynamicTopicsCache`. It keeps, for each chat, the identifier of the chat, the date of its last message, and the words of its dynamic topic source information with their weights, because reading the titles on the forge is the expensive part, and the best words of a chat depend on the other chats that the list shows. The topics are ranked again each time, which is cheap. A chat whose last message did not change is never read again. A new or changed chat gets its words at once from the title, the first messages, and the folders, and gets the titles of its issues and pull requests when the forge answers. A chat whose titles could not be read tries again once in the next run of Heidrun Code. The cache keeps the 200 chats with the newest last message (`stores/dynamic_topics.ts`).
- The method "Language model" reads the title and the first messages that the developer typed (two parts of the dynamic topic source information) of each chat that the list shows. The messages of the coding agent, the folders, the files, the issues, and the pull requests are never sent. At each run, Heidrun Code finds the chats that have no topics, or whose last message is newer than their topics. When there is none, or when the method is "Keyword", Heidrun Code makes no call. Otherwise it makes one call to a coding agent, through the Tauri command `coding_agent_ask` that the clustered dynamic topics use too (`codex` when it is installed, `claude` otherwise), for at most 20 chats. A longer list is sent in several calls, one after the other. The prompt holds the dynamic topics that already exist, the most used first and at most 100, and tells the coding agent to reuse one when it fits, so that "sidebar", "side bar", and "right panel" do not become three dynamic topics. The coding agent answers with a JSON array that has one item `{"conversation", "topics"}` for each chat, where `conversation` is the number of the chat in the prompt, and `topics` holds one to three dynamic topics of one or two words, in lower case, in English (`lib/language_model_topics.ts`). Heidrun Code saves the topics only when each chat appears exactly once and every topic follows these rules. A wrong answer, or a failed call, saves nothing, and the same chats at the same last message are not asked again before the next start of Heidrun Code, or before the developer chooses the method "Language model" again.
- The cache of the method "Language model" is in the `localStorage` of the web frontend, under the key `heidrun.languageModelTopicsCache`. It keeps, for each chat, the identifier of the chat, the date of its last message, and its topics, for the 200 chats with the newest last message (`stores/language_model_topics.ts`). A chat whose last message did not change is never sent again. A chat whose last message changed keeps its old topics on the screen until its new topics arrive, and keeps them when the call fails. The cache of the method "Keyword" and the cache of the method "Language model" are separate, so the developer can change the method without losing either one.
- Under the radio buttons of the choice "Extraction method", a line in muted color says why the last call of the method "Language model" gave no topic (no coding agent, a failure, or a wrong answer). The line shows only while the method is "Language model" and while the last call gave no topic. It is separate from the line of the clustered dynamic topics.
- Both methods do nothing while the option "Enable dynamic topics" is off: the method "Keyword" makes no entry and reads nothing on the forge, and the method "Language model" makes no call, even in the middle of a run of several calls (`stores/dynamic_topics.ts`, `stores/language_model_topics.ts`). Switching the option on starts a normal run.
