# Past chats sidebar section: clustered dynamic topics

- Created: 13 October 2026
- Last updated: 23 October 2026
- Status: Maintained rules for agents and tools
- Related framing: [Project instructions](../../../../../../AGENTS.md)
- Related rules: [Glossary of Heidrun Code](../../../../glossary/index.md), [Glossary of Heidrun Code: dynamic topics](../../../../glossary/dynamic_topics.md)

This file is a part of the rules of the user interface of Heidrun Code. The words are defined in [glossary/index.md](../../../../glossary/index.md) and [glossary/dynamic_topics.md](../../../../glossary/dynamic_topics.md).

- The section "Dynamic topics" of the Settings window has a second part, "Clustered dynamic topics": a Bootstrap 6 switch (`switch`) with the label "Enable clustered dynamic topics", a circled question mark just after the label, and a button "Rebuild the clusters". The switch is the option `clusteredDynamicTopics` of the settings, and the default is off, because the method makes calls to a coding agent. The part has no help paragraph under the switch. A click on the circled question mark opens an information card below it, with a title (the question mark icon and the text "Clustered dynamic topics"), then three blocks: "What it is" (a clustered dynamic topic is the name of a group of dynamic topics that have a close meaning, so one subject has one label), "What Heidrun Code sends" (only the short labels of the raw dynamic topics, and never the text of a chat, to the coding agent `codex` or `claude` that is installed on this computer), and "When the option is off" (Heidrun Code shows the raw dynamic topics and makes no call). The button is disabled while the option is off and while a call runs, and it shows a Bootstrap spinning wheel while a call runs. A line under the button says why the last call gave no cluster (no coding agent, a failure, or a wrong answer), only while the option is on.
- While the option "Clustered dynamic topics" is off, the dynamic topic bar and the topics on the row of each chat show raw dynamic topics, and Heidrun Code makes no call. While it is on, both show clustered dynamic topics, so a button of the dynamic topic bar matches what the rows show, and a click on a button shows only the chats that have the cluster. A raw dynamic topic that the translation table does not know yet is shown as its own cluster, until the table has its row.
- The clusters come from the translation table, the file `topic_clusters.json` in the data folder of Heidrun Code: it maps each raw dynamic topic, in lower case, to the name of a cluster. Chats of Claude and of Codex share one table, because a raw dynamic topic does not depend on the coding agent. A row is never changed, and never leaves the table, except at a rebuild. At each run, Heidrun Code finds the raw dynamic topics of the chats that the list shows, after the keyword topics are ready, and that the table does not know. When there is none, when the option is off, or when the option "Enable dynamic topics" is off, Heidrun Code makes no call. Otherwise it makes one single call to a coding agent, through the Tauri command `coding_agent_ask`, with a prompt that holds only the names of the existing clusters and the new raw dynamic topics. The coding agent is `codex` when `command -v codex` finds it in the login shell, and `claude` otherwise. When neither exists, the raw dynamic topics stay as they are. The coding agent answers with a JSON array that has one item `{"topic", "cluster"}` for each new raw dynamic topic, and a name of one or two words for each cluster. Heidrun Code saves the rows only when each new raw dynamic topic appears exactly once. A wrong answer, or a failed call, saves nothing, and the same set of new raw dynamic topics is not asked again before the next start of Heidrun Code, before a rebuild, or before the developer switches the option off and on.
- The button "Rebuild the clusters" empties the translation table, on the disk too, and asks for the clusters of all the raw dynamic topics of the chats that the list shows, in one call. A call that started before the rebuild saves nothing. A circled question mark on the right of the button opens an information card with the blocks "What it is", "How it works", and "What Heidrun Code sends".
- The option "Clustered dynamic topics" works with both methods: the clusters are made from the raw dynamic topics of the method that the developer chose.
