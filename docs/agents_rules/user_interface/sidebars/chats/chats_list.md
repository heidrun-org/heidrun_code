# Past chats sidebar section: the list of chats

- Created: 13 October 2026
- Last updated: 23 October 2026
- Status: Maintained rules for agents and tools
- Related framing: [Project instructions](../../../../../AGENTS.md)
- Related rules: [Glossary of Heidrun Code](../../../glossary/index.md), [Data layer access](../../../data_layer_access.md)
- Related issue: [issue 250](https://github.com/heidrun-org/heidrun/issues/250), [issue 557](https://github.com/heidrun-org/heidrun/issues/557), [issue 617](https://github.com/heidrun-org/heidrun/issues/617)

This file is a part of the rules of the user interface of Heidrun Code. The words are defined in [glossary/index.md](../../../glossary/index.md).

- The Past chats sidebar section is a sidebar section of the right sidebar. It lists the chats of the selected workspace.
- The name of the Past chats sidebar section on the screen is "Past chats". The tooltip of its icon in the sidebar icon bar, and the label that a screen reader reads for the section, show this name. The sidebar section starts with the title "Past chats", at the left, in the same kind of line as the title "File explorer" of the File explorer sidebar section: the text is one line long. The look of the title is in [sidebars_appearance.md](../../../web_styling/sidebars_appearance.md). The title is always shown, whatever the state of the list (loading, error, no workspace, no chat). The title never scrolls: only the part under it scrolls, with the header of the sidebar section.
- The folder of the selected workspace gives the chats: the root of the repository that holds the folder of the workspace. A chat that a coding agent saved for another folder, a worktree of the workspace included, is not in the list. The list shows the chats that Codex compressed (`.jsonl.zst`) like the others. The statistic of the AI cost is the one place that also counts the chats of the worktrees and of the sub-folders ([statistics_ai_cost.md](../../window/statistics_ai_cost.md)).
- Below the separator, the list shows the title of each chat of the chosen coding agent, in the order of the Chats sort dropdown menu. The first start gives the sort key "Last updated" and the order "Descending": the chat with the most recent activity is first. The title of Claude comes from the last title record of the file of the chat. The title of Codex comes from the index of Codex. A chat without a title shows its first message. A chat without a title and without a message is not in the list.
- A review chat of Codex is not in the list, and is not in the SQLite file of the package `data_layer_coding_agents` ([issue 557](https://github.com/heidrun-org/heidrun/issues/557)). Codex starts a review chat to review an approval request: its first record (`session_meta`) has the source `{"subagent":{"other":"guardian"}}`, and Codex names it "Guardian review". The developer typed none of its messages.
- Each row of the list has a Bootstrap button group at the right of its title, with two buttons that show only an icon, each with a title. The first button (the icon of the coding agent, as the tabs show it: `claude` for Claude and `openai` for Codex; the title is "Open in the Claude app" or "Open in the Codex app") opens the chat in the desktop application of the coding agent, with the address `claude://code/<session identifier>` or `codex://threads/<session identifier>`. The second button (the icon of Heidrun Code, the goat: `heidrun-goat-only` of the component `Icon`, drawn from `data/images/heidrun_icon_goat_only.svg`; the title is "Open in Heidrun Code") opens a new tab of the selected workspace, named after the chat, in the folder of the workspace, and types `claude --resume '<session identifier>'` or `codex resume '<session identifier>'` in it. A session identifier with a character other than a letter, a digit, or a dash is refused, so that no shell command can be built from it. The address of Codex comes from its documentation; the address of Claude is documented for the mobile application only, so the Claude button is not proven in the desktop application. The capability `opener:allow-open-url` allows only the schemes `claude://` and `codex://` besides the default ones.
- The list shows 5 chats at the start. Under the list, two buttons stay visible all the time: "Show more" on the left and "Show less" on the right. "Show more" is disabled when the workspace has no more chats of the chosen coding agent. "Show less" is disabled when the list has no more chats than the next lower number allows. Each click on "Show more" asks for more: 10 chats, then 20, then 50, then 50 more at each click. Each click on "Show less" goes one step back, down to 5 chats, and cuts the list at once without reading the files again. While "Show more" waits for the answer, it shows a small spinning wheel at its right end, close to the right border, and both buttons are disabled. The wheel sits on top of the button and takes no room, so neither button changes its size or its place when the wheel appears or goes away. The label of each button stays in the center. The wheel is centered with `top-0 bottom-0 my-auto`, never with a `transform`: a utility class with `transform` and `!important` stops the rotation of the wheel. A click on "Show more", a click on "Show less", and a change of the sort key call the Tauri command `chats_list`, which reads the SQLite file only and opens no chat file, so the cost does not grow with the number of chats of the workspace. The chat files are read by the Tauri command `chats_synchronize`, which the list calls first when the Past chats sidebar section opens. The list starts again with 5 chats when the developer selects another workspace.
- The rows of the list use the Bootstrap list group. The separators, the margins, and the background of a row under the pointer are in [sidebars_appearance.md](../../../web_styling/sidebars_appearance.md).
- The button of the Past chats sidebar section shows no number.
- The list copies the new chats into the SQLite file with `chats_synchronize`, then reads them with `chats_list`, when the Past chats sidebar section opens, when the developer selects another workspace, and after a delay while the Past chats sidebar section is on the screen. The delay is the option "Read the chats again every" of the section "Past chats" of the Settings window: 5 seconds, 10 seconds (at first), 30 seconds, or 1 minute. A change of the delay starts the count again. The rules of the section are in [past_chats_settings_section.md](past_chats_settings_section.md).
- The list gets all its data from the package `data_layer_coding_agents`. The desktop application and the web page never read a chat file for the list. The rule, the exceptions, and the check are in [data_layer_access.md](../../../data_layer_access.md).
- The ideas for later are in [issue #250](https://github.com/heidrun-org/heidrun/issues/250).
