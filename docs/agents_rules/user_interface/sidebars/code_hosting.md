## Code hosting

The Code hosting sidebar section shows what lives on GitHub or on GitLab for the repository of the selected workspace ([issue #370](https://github.com/heidrun-org/heidrun/issues/370)). The Source control sidebar section shows only the local Git repository. The search line of each list, the saved searches, and the two windows of the saved searches are in [code_hosting_search.md](code_hosting_search.md).

- The header holds the title "Code hosting" at the left, and one button at the right: "Refresh" (`arrow-clockwise`), which shows only an icon ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). The buttons "Save this search" and "Edit the saved search" are not in the header: each list has its own ([code_hosting_search.md](code_hosting_search.md)). Only the header stays fixed at the top of the sidebar section: the part that starts at the list "Issues" scrolls, with the search line of each list.
- Below the header, two collapsible lists, one above the other. Each list header has an arrow that folds the list, the title, a smaller circled question mark for search help immediately after the title, and a badge with the number of items. A click anywhere on the header, on the arrow, on the title, on the badge, or on the empty space between them, folds or unfolds the list ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). The arrow and the title are one button, so that the keyboard folds the list too. The circled question mark is a separate button: opening the help never folds the list.
- The top list is "Issues". The bottom list is "Pull requests" for a repository on GitHub, and "Merge requests" for a repository on GitLab. A list that has no item says "No open issue.", "No open pull request.", or "No open merge request.". Under the title of a list that is not folded, in this order: its search line, its line of saved searches, a separator, then its rows ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). A folded list hides its search line, its line of saved searches, and its separator with its rows.
- Each list shows the open items only. A list reads at most 100 items. When a list reaches 100 items, a line under it says that the list is too long.
- A row has three lines, and every row has the same height, whatever the text. The first line shows the number in grey, then the title. The number starts with `#`, except for a merge request of GitLab, which starts with `!`. The second line is a small detail line in grey: who opened the item and how long ago ("jeromeetienne opened 3 days ago"), with " · Draft" added for a draft pull request or merge request. The third line is a small detail line in grey: the labels of an issue, each one as a small pill in its own color, as GitHub draws it (a label without a color uses the neutral color), as high as its line less one pixel above and below, so that its border is never cut, or "No label", or, for a pull request or a merge request, the branch with the changes, an arrow, and the branch that receives them. A line that does not fit ends with an ellipsis. While the pointer is over a row, a title that does not fit scrolls to its end, like the lines of the information cards of the Past chats sidebar section. The number does not scroll.
- A row has no button: the whole row is one part that opens the information card. A row takes the whole width of the sidebar section, from its left line to its right line. The corners of a row, the line under it, and its background are in [sidebars_appearance.md](../../web_styling/sidebars_appearance.md).
- A row is the part of an information card, the same kind of card as the cards of the Past chats sidebar section. A click on the row opens the card at the right of the row, because the sidebar is the left sidebar. A second click closes it. The card has the content of the details of a reference in the information card of the references line ([references_line.md](chats/information_cards/references_line.md)), in the same order ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)): the repository (a link to its web page) and the date of the creation, with the four buttons "Open in Heidrun Code", "Open in GitHub" (or "Open in GitLab"), "Copy the GitHub web address" (or "Copy the GitLab web address"), and "Let's chat about this issue" (or "Let's chat about this pull request") at the right of this line; the whole title with its number after it, never in a scrolling line; the state in a pill; a separator; the beginning of the description, and the labels or the two branches; a separator; and the person who opened it. The button "Open in GitHub" is the way to open the web page of the item in the web browser, the button "Copy the GitHub web address" writes the address of this same web page into the clipboard of the computer, and the name of the repository opens the web page of the repository. Each label is a button that adds the label to the search of the list, or removes it, and runs the search at once ([code_hosting_search.md](code_hosting_search.md)). The size of a label of the card is in [sidebars_appearance.md](../../web_styling/sidebars_appearance.md).
- A click on a row does not open the card at once ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). Heidrun Code first reads the details from the hosting service, through the Tauri command `forge_cli_cached`, which keeps each answer for ten minutes. The card opens when the reading is done, with everything in it, so that its content never changes while the developer looks at it: no text "Loading", and no line that moves. When the answer is in the cache, the card opens with no wait. When the reading takes more than 0.3 second, a small spinning wheel shows at the right end of the bottom line of the row, with some space around it, until the card opens. When the reading takes less than 0.3 second, the wheel never shows. A second click on the row, the key Escape, a press outside the row, or a loss of the keyboard focus cancels the opening, and the card does not open. When the hosting service does not answer, the card opens with the message that the hosting service cannot be read.
- The lists are read when the sidebar section is shown, when the repository of the selected workspace changes, and when a search changes, through the Tauri command `forge_cli_cached`: the kept answer of the same list, with the same search, is used whatever its age, so GitHub or GitLab is asked only when no answer is kept ([issue 870](https://github.com/heidrun-org/heidrun_code/issues/870)). Only a click on "Refresh" asks GitHub or GitLab again for the two lists, keeps the new answer, and keeps the search of each list. When the hosting service does not answer, an answer that is at most seven days old replaces the failure. After a refresh, the list then shows its old rows under a red line: "The refresh failed. This list is from {time}.", then the first line of the failure, or the message of the GitHub rate limit with its reset time ([issue 890](https://github.com/heidrun-org/heidrun_code/issues/890)). The refresh uses the Tauri command `forge_cli_cached_with_source`, which gives the failure and the time of the kept answer.
- When the workspace is not a Git repository, or when the repository has no remote address, the sidebar section says so, and shows no list. When the remote address cannot be read, the sidebar section shows the first line of the failure, and shows no list. When `gh` or `glab` fails for a list (no login, no network), this list shows the first line of the failure under its search line, shows no row, and the other list is not changed.
- The lists are read with `gh issue list` and `gh pr list` on GitHub, and with `glab api` on GitLab, with the author, the date, and the labels or the branches of each item. These calls only read.
- The icon of the Code hosting sidebar section in the sidebar icon bar has no number. It is the logo of the hosting service of the repository of the selected workspace: `github` for GitHub, and `gitlab` for GitLab. A host that is not GitHub is read as GitLab, as the lists do. The icon is a `cloud` when the hosting service is not known: no workspace, not a Git repository, or no remote address. Heidrun Code finds the hosting service from the remote address only, with no call to `gh` or `glab`, so the icon does not wait for the lists, and it changes when the developer selects another workspace.
