## Saved searches

The words are defined in [glossary/code_hosting.md](../../glossary/code_hosting.md) ([issue #374](https://github.com/heidrun-org/heidrun/issues/374)).

- The button "Save this search" of a list is disabled while its search field is empty, and while its text is already the search of a saved search that shows in this list. It opens the window "Save this search", a modal window like the window "Create a custom launcher". The window shows, in this order: the title of the list that the saved search is for, the label "Level" with the buttons "User" and "Workspace" and one sentence under them that says where the saved search shows, a field "Name" with the focus, the search shown under it, and the buttons "Save" and "Cancel" ([issue #822](https://github.com/heidrun-org/heidrun/issues/822)). The button "User" is chosen first. The button "Workspace" is disabled, and its title says why, while no workspace with a workspace folder is selected. The key Enter saves, and the key Escape closes the window without a change. "Save" is disabled while the name is empty. A name that already exists at the chosen level in this list keeps the new search under that name, and the window says so. A name that exists at the other level, or in the other list only, is a new name. After the save, the new saved search runs in this list.
- Under the search line of a list, a line shows the button "All", then one button for each saved search of this list that shows in the selected workspace: first the saved searches of the user level, then the saved searches of the workspace level, each group in the order of saving. A click on a button fills the search field of this list and runs the search in this list. The button "All" writes `is:issue` in the search field of the list of issues, and `is:pr` in the search field of the list of pull requests, as GitHub reads them ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). On GitLab, the button "All" writes no search, because GitLab cannot read these words. The button of the search that runs now in this list is filled and pressed, and "All" is filled and pressed when no search runs in this list, or when the search is the one that "All" writes. A list that has no item for this search says "No open issue." and not "No issue matches the search.". A name that does not fit ends with an ellipsis. The line is not shown while the list has no saved search that shows in the selected workspace. A separator is under this line, or under the search line when the line of saved searches is not shown, and the rows of the list are under the separator.
- A button of a saved search has an information card tooltip, not the HTML attribute `title` ([issue #822](https://github.com/heidrun-org/heidrun/issues/822)). The information card tooltip is defined in [glossary/status_bar.md](../../glossary/status_bar.md). It opens below the button after a delay of 1.5 seconds, while the pointer stays over the button or the button keeps the keyboard focus, and it closes at once when they leave. Its heading is the name of the saved search. It has three blocks:
  - "Search": the search in full.
  - "Level": "User: the saved search shows in every workspace." for the user level, and "Workspace <name of the selected workspace>: the saved search shows only in this workspace." for the workspace level.
  - "List": the title of the list: "Issues", "Pull requests", or "Merge requests".
- The button "Edit the saved search" of a list is disabled while no saved search runs in this list (when "All" is pressed, or when the search is not saved). Otherwise it opens the window "Edit the saved search" for the saved search that runs in this list: the title of the list, the label "Level" with the buttons "User" and "Workspace" (the level of the saved search is chosen) and its sentence, a field "Name", a field "Search", and the buttons "Save", "Cancel", and "Delete". "Save" is disabled, and a message says why, while the name is empty, the search is empty, or the name is the name of another saved search of the same list at the chosen level. A change of the level moves the saved search to the end of the saved searches of the new level. After "Save", a saved search that ran still runs, with its new search. "Delete" asks for a confirmation in a dialog that names the saved search, unless the developer unchecks "Ask before deleting a saved search" in the section General of the Settings window (checked by default).
- A saved search has one of two levels ([issue #822](https://github.com/heidrun-org/heidrun/issues/822)), and each list has its own saved searches: a saved search of one list never shows in the other list.
  - A saved search of the user level shows in every workspace. Heidrun Code keeps it in the option `codeHostingSavedSearches`, with the other options.
  - A saved search of the workspace level shows only in the workspace where the developer saved it. Heidrun Code keeps it in the option `codeHostingWorkspaceSavedSearches`, under the workspace folder of this workspace, because a workspace folder is the same at every run of Heidrun Code. A workspace that is closed keeps its saved searches, and a workspace that opens later on the same folder shows them again. A workspace with no workspace folder shows only the user level.
  - Each option holds two lists of saved searches, `issues` and `requests`. A saved search that was saved before the levels existed is at the user level.
  - An entry without a name or without a search as text is dropped when the options load, and a workspace folder that has no saved search is dropped too. A saved value that is one single list, from before [issue #607](https://github.com/heidrun-org/heidrun/issues/607), is copied into both lists when the options load, so that nothing is lost.
