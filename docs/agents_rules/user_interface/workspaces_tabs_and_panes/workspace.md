## Workspace

- The [workspace folder](../../glossary/workspaces_tabs_and_panes.md#workspace-folder) is saved separately from pane folders, by Herdr session and workspace identifier, and survives restarts. Workspace features use this folder or its repository.
- New terminals, coding agents, resumed chats, and commands in new panes start in the workspace folder. Guard checks use the starting folder, or the actual folder for an existing pane. Launchers keep their configured starting folders.
- Existing workspaces restore the saved folder, explicit creation metadata from `heidrun_code_ctrl` in the Herdr token `heidrun_workspace_folder`, or Herdr's `worktree.checkout_path`. Once saved, the folder stays fixed even if the token changes. Otherwise, a notice asks for the original folder once; no pane folder is adopted. New pane creation waits for this choice. Existing pane commands remain available.
- Creation without a folder uses the absolute home folder. Folders outside Git follow the same rules.

- One workspace is selected at a time. A `workspace_focused` event from Herdr selects the requested workspace in the window, even when Herdr already focused that workspace. A new `heidrun_focus_request` token published by `heidrun_code_ctrl` also selects that workspace, including when Herdr's focus is unchanged. Repeated metadata with the same token and unrelated events keep the current workspace selected.
- The workspace status bar section is the first status bar section, at the left end of the status bar. It shows a status dot and the name of the selected workspace. A click on it opens its information card above the section. The information card does not open when the mouse moves over the section.
- The status dot is always visible, and it sits before the name, in the same place as the dot of a tab. When an agent in another workspace is blocked or has finished, the dot has the color of that status, and it follows the cards of the Needs you sidebar section. Otherwise, the dot shows the status of the selected workspace. A workspace without an agent gets a hollow ring.
- The information card of the workspace status bar section is titled "Workspace" and is 432 pixels wide. It gives the folder, the Git branch, the repository, the number of tabs, and the number of agents of the selected workspace. The folder is shown on one line, under the rules of the section "Text that must stay on one line" (in [layout.md](../window/layout.md)): while the pointer is over the information card, a folder that does not fit scrolls sideways to its end, and it shows its beginning again when the pointer leaves. The folder path and Git branch each have a button that copies their value. The repository is the web address of the remote `origin`, shown as a link: a click on the link opens the repository in the web browser, and the card stays open. Without a Git remote, the row says "No repository", with no link. Under the details, it lists the workspaces. Each workspace shows its name beside the status dot on the left, and its branch in smaller, muted text on the right when it belongs to a Git worktree. A tooltip for a workspace row has the workspace name as its heading, followed by the Git branch and the full folder path. Long paths wrap. The tooltip appears beside the row with an arrow at the bottom left. The rename and close icons appear over the branch on hover without moving the row contents. A click on a workspace selects it, and closes the information card.
- **The order of the workspaces never changes with the status dot or with the presence of an agent.** The list shows the workspaces in the order of Herdr, which is the number of the workspace. A workspace without an agent can sit above a workspace with an agent, and starting, blocking, finishing, or stopping an agent moves no workspace. Only the developer moves a workspace, by drag and drop, with the keyboard, or with the command search. The shortcuts that select a workspace (Command and a digit, Option+Command+Up arrow, and Option+Command+Down arrow) use this same order. The store `session.ts` has one list of workspaces, `workspaces`, and no other list that orders them by agent ([issue 417](https://github.com/heidrun-org/heidrun/issues/417)).
- The list of workspaces has no separator line between the workspaces, and no space between two rows: between the two separator lines, the pointer is always on a workspace. Each row is 32 pixels tall, with the padding inside the row. One separator line sits between the list and the entries "Open workspace from folder" and "Open workspace from this repo worktree" at the end of the information card.
- The space after the workspace status bar section is in [status_bar_appearance.md](../../web_styling/status_bar_appearance.md).
- Each workspace of the list offers the rename of the workspace, the close of the workspace, and the move of the workspace by drag and drop. The rename puts a text field in the place of the name in the status bar. A double click on the workspace status bar section does not rename the workspace.
- The entry "Open workspace from folder" asks for a folder, then creates the workspace with the name of the folder and selects it at once, with its first tab and its first pane. Herdr creates this first tab with the workspace, so Heidrun Code creates no other tab. The pane of this first tab runs the default command of a new tab, the option `newTabCommand` of the settings, the same as a plain click on the plus button of the tab bar ([tabs.md](tabs.md)). With "terminal", the pane is the shell that Herdr started in the folder. With Claude Code, Codex, or Antigravity, Heidrun Code renames the first tab after the coding agent and starts the coding agent in the first pane ([issue 379](https://github.com/heidrun-org/heidrun/issues/379), [issue 688](https://github.com/heidrun-org/heidrun/issues/688)).
- The entry "Open workspace from this repo worktree" sits after "Open workspace from folder" in the information card. It is disabled when there is no selected workspace or the selected workspace has no repository root. A disabled entry has no hover treatment or title tooltip. The cursor over the information card is in [status_bar_appearance.md](../../web_styling/status_bar_appearance.md). The entry opens a centered window titled "Open workspace from the selected repo's worktrees". Reading begins when the developer selects the entry. When the read finishes within half a second, the window opens with the worktrees already shown. Otherwise, it opens in the loading state and shows the worktrees when the read finishes. The window lists every existing worktree of the selected workspace's repository, including the main checkout, and refreshes the list each time it opens or when the developer selects the refresh button in the header. During a refresh, the current rows stay visible until the refreshed list is ready. The rows can be sorted by name, creation time, or latest commit time, in either order. Each row shows a folder icon beside its branch or detached-head name, its folder path, its creation time when available, and the time of its latest commit when available. A separator appears between rows. Selecting a row selects the existing workspace for that folder, or creates and selects a workspace when none exists. A copy button in the top right of each row copies the folder path and shows a check for two seconds after a successful copy ([issue 685](https://github.com/heidrun-org/heidrun/issues/685)).
- The Needs you sidebar section shows the same list of workspaces, in the same order, with the same selection and the same drag and drop, but without the rename and the close ([needs_you_workspaces.md](../sidebars/needs_you_workspaces.md)).
- Two other ways to switch workspace: the command search with ⌘K, and the shortcut Option+Command+Up arrow or Option+Command+Down arrow.
- In Zen Mode, the workspace shortcuts and command search keep working while the top bar, sidebars, and status bar stay hidden. Zen Mode remains active and shows the pane last focused in the selected workspace and its selected tab.
- Heidrun Code saves the identifier of the selected workspace each time that the selection changes, in the option `selectedWorkspaceId` of the store `settings.ts`. At the next start, Heidrun Code selects this workspace again, with its last tab and its last pane. When this workspace does not exist any more, Heidrun Code selects the workspace that Herdr has focused, or the first workspace.
- Herdr events refresh the workspace list; no timer reads its snapshot. See [workspace command integration](workspace_commands.md) for refresh, focus, and creation folder rules.
