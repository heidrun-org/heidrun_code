## Tabs

- The tab bar sits at the top of the viewport, inside its border. It shows the tabs of the selected workspace, one entry for each tab. It has no workspace selector: the workspace status bar section has it.
- A click anywhere on a tab, padding included, selects the tab. The viewport then shows the panes of that tab. The close button of the tab is the only exception: a click on it closes the tab.
- A tab switch never creates a terminal again. The viewport keeps the panes of every tab that the developer opened since Heidrun Code started, and hides the panes of the tabs that are not selected, with their place and their size. A new terminal is empty until Herdr draws its screen, so a new terminal at each tab switch makes the pane blink. A tab that the developer has not opened yet has no terminal. A pane that leaves its tab, because it is closed or pinned, loses its terminal ([issue 495](https://github.com/heidrun-org/heidrun/issues/495)).
- The plus button at the end of the tab bar creates a new tab at once, and opens no window. The pane of the new tab runs the default command of a new tab, the option `newTabCommand` of the settings: "terminal" (a shell, the default), "claude" (Claude Code), "codex" (Codex), or "agy" (Antigravity). The Antigravity choice is available only while Antigravity is switched on in the Settings window. With a coding agent, the pane starts a free coding agent with its default model and no starting prompt, and the tab is named after the command. A shift click on the plus button starts a terminal in the new tab, whatever the default command is ([issue 328](https://github.com/heidrun-org/heidrun/issues/328), [issue 465](https://github.com/heidrun-org/heidrun/issues/465), [issue 688](https://github.com/heidrun-org/heidrun/issues/688)). Command+Shift+T does the same as a shift click: it creates a terminal tab directly, whatever the default command is. Neither shortcut opens a New pane window. The shortcut Command+T does the same as a plain click on the plus button: it creates a new tab and starts the default command of a new tab ([issue 340](https://github.com/heidrun-org/heidrun/issues/340)). A pane that the developer drags and drops on the plus button moves into a new tab: the rules are in [pane_move.md](pane_move.md) ([issue 825](https://github.com/heidrun-org/heidrun/issues/825)).
- The close button of the tab, Command+W, and the command palette call the same closing function, which refuses to close the last tab of its workspace. Command+W must be pressed twice within two seconds for the same selected tab. The first press shows "Press ⌘W again to close this tab"; the second press closes the selected tab, including every pane of the selected tab. A held key does not count as a second press. The two presses confirm the keyboard action; the close button keeps its confirmation dialog when "Ask before closing" is on.
- When the developer closes the selected tab, the focus goes to the pane that had the focus most recently in another tab of the same workspace, in the [pane focus history](pane_focus_history.md), and the tab of that pane becomes the selected tab. The closed tab can hold several panes of the history, so the search skips all of them. When the history holds no such pane, the tab that Herdr makes active becomes the selected tab. Closing a tab that is not selected changes nothing ([issue 862](https://github.com/heidrun-org/heidrun_code/issues/862)).
- A workspace always has at least one tab. When the developer closes the last tab of a workspace, from the close button of the tab, Command+W, or the command palette, the application does not close the tab, and shows the error notification "You cannot close the last tab of a workspace." The error notification appears at once, without the confirmation dialog of the setting "Ask before closing" ([issue 424](https://github.com/heidrun-org/heidrun/issues/424)).
- The Settings window has the choice "Default command of a new tab" in its section "Coding agents", under the heading "Default command of a new tab": a Bootstrap 6 button group of radio inputs (`btn-group` with `btn-check btn-outline theme-secondary` labels), "Terminal", "Claude Code", "Codex", and "Antigravity" when Antigravity is switched on, and one line of help under them ([issue 328](https://github.com/heidrun-org/heidrun/issues/328), [issue 688](https://github.com/heidrun-org/heidrun/issues/688)).
- The developer reorders the tabs by pressing a tab, moving the mouse, and releasing the button where the tab goes. The same holds for the list of workspaces and for the list of notes. The reorder uses the pointer events of the page, and never the drag and drop of the browser: the window of Heidrun Code receives the image files that the developer drops from Finder, so the native window takes every drag and drop, and the page gets no drag event of the browser. A press that moves less than 5 pixels is a click. The key Escape cancels the move.
- While the developer moves a pane, a tab of the tab bar under the pointer is selected at once: see [pane_move.md](pane_move.md).
- In normal mode, a developer switches tab often, so the tabs are always visible.
- A workspace has few tabs, twenty tabs is extremely rare. So each tab is large, with generous horizontal padding.
- Each tab shows a small icon between its status dot and its name: the Claude icon, the OpenAI icon for Codex, the Google icon for Antigravity, or the terminal icon. A pane with an agent always beats a terminal. Among the panes with an agent, the pane that decides the color of the status dot gives the icon (blocked, then working, then done, then idle). When two panes have the same status, the selected pane wins, then the focused pane, then the first pane.
- The shortcut Option+Command+Left arrow or Option+Command+Right arrow selects the previous or the next tab.
- In Zen Mode, those shortcuts keep working while the tab bar stays hidden. Zen Mode remains active and shows the pane last focused in the selected tab. It remembers that pane separately for each tab during the current Zen Mode run.
