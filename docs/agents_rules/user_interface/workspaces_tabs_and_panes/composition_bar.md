## Composition bar

- The section "Coding agents" of the Settings window has the switch "Show the composition bar when starting a coding agent", with a circled question mark and an information card. The switch is off by default and is saved across restarts. On: new panes that start directly with a coding agent show the composition bar, including new tabs, split panes, the first pane of a new workspace, resumed chats, and launchers of the kind Coding agent or whose command starts with `claude`, `codex`, or `agy`. When Heidrun Code starts, every pane that already runs Claude Code, Codex, or Antigravity (Herdr keeps these panes running after Heidrun Code quits) also opens its composition bar, because the state of a composition bar is not saved: only the panes of the first list that Herdr sends after the start, and never a plain terminal ([issue 865](https://github.com/heidrun-org/heidrun_code/issues/865)). Returning to or rerunning an existing launcher pane preserves its composition bar visibility. Off: those panes start with the composition bar hidden. Plain terminals start with the composition bar hidden. Changing the setting does not change existing panes. The header toggle button remains available in every pane.

- The drop of image files: only an open composition bar accepts a drop, whichever pane has the focus, and the window shows where a drop goes. The rules, the finding of the composition bar under the pointer, and the feedback are in [composition_bar_drop.md](composition_bar_drop.md). A file that is not an image, dropped on a composition bar, gets the message "This file is not an image". The same file is never added twice to one composition bar.
- The composition bar sits under its pane's terminal, inside the border of the pane. It opens after a click on that pane's header toggle button, or when a new pane starts directly with a coding agent and the saved setting "Show the composition bar when starting a coding agent" is on. A closed composition bar takes no height. Each pane keeps its own open or closed state, images, and text. Switching focus does not open, close, or move a composition bar.
- More than one composition bar can be open. Each composition bar stays inside its pane and takes space from that pane's terminal, whether or not that pane has the focus.
- Zen Mode keeps the composition bar inside the visible pane, under its terminal, with the same position and behavior.
- When the composition bar has images, its first line holds one small picture for each image, and nothing else. With no image, this line does not exist, and the composition bar has one line. Each picture is 144 by 96 pixels, and shows a large image icon while its preview loads. Each picture has a round-cornered button of 30 pixels in its top right corner that removes it. Removing the last image keeps the composition bar open and removes the first line. The composition bar shows no text that counts the images.
- The last line, which is the only line when there is no image, holds from left to right: the plus button, the text input, the button "Send", and the push-to-talk button (only when the voice input is on), which is the last control at the right. The plus button is on this line, so it never moves when an image is added or removed. It opens the file picker of the system, which accepts several image files. The chosen images go to the composition bar whose plus button opened the file picker, even if focus changes before the file picker closes.
- The spaces, the sizes, and the hover background of the composition bar and of the buttons of its last line are in [panes_appearance.md](../../web_styling/panes_appearance.md). The buttons of the last line are icon buttons with no text. Each has a label for the screen readers, and the button "Send" has a title that names its key, Enter.
- The text input takes several lines. The text of a recording goes at its end. It has a label for the screen readers and a placeholder, and it grows with its lines up to 160 pixels, then scrolls. An empty text input is one line high, whatever the length of the placeholder. The key Enter sends, and the keys Shift and Enter write a new line. During recording and transcription, the level bars and the elapsed recording time are inside the text input at its right end, with a small X button immediately to the left of the level bars that cancels voice input without changing the text or images or closing the composition bar, as [settings_voice_input.md](../window/settings_voice_input.md) says.
- The animation of the level bars during transcription ([issue 820](https://github.com/heidrun-org/heidrun/issues/820)): when Whisper starts, the level bars flatten to dots in 0.45 second. Then one green sine wave, with a glow, goes across the dots from the left to the right in about 1.5 seconds: each dot goes up, back, down, and back, and the dots outside the sine wave keep the muted color. After a rest of 0.5 second, the sine wave starts again, until the transcription ends. The green is the theme variable `--voice-wave`, and the recording time stays still. With the system setting "Reduce motion", nothing moves: the flat dots only turn green. The numbers are in `components/VoiceLevel.vue`.
- When an image arrives, the text input of the pane's composition bar gets the keyboard. The key Enter in the text input (without Shift), and the button "Send", paste each image in that pane one after the other, with a wait of half a second. When the text is not empty, Heidrun Code then writes the text in that pane and presses Enter in that pane. When the text is empty, Heidrun Code writes nothing and presses nothing, so the developer keeps the keyboard in the terminal. Then Heidrun Code clears the text, the composition bar stays open, and the keyboard goes back to that pane's terminal. A change of focus does not move text or images to another pane.
- When the microphone is open, or Whisper still changes the speech into text, the key Enter and the button "Send" first stop the recording, wait for the text, and add it to the text input. Only then do they send the images and the whole text. The button "Send" is dimmed during this wait. When the recording or the change into text fails, nothing is sent, the composition bar stays open, and the line under the text input tells why.
- When a paste fails, the images that were not pasted and the text stay in the composition bar.
- Every pane has a toggle button in its header that shows and hides that pane's composition bar. The button is the first of the tool buttons of the header, before the macro menu, whether the voice input is on or off. Its icon is a text input with a cursor (`input-cursor-text`), it has a label and a title, and it is pressed and orange while that pane's composition bar is open, like the pressed pin button. One click opens that pane's composition bar with no image, and the next click hides it. The composition bar has no button "Close".
- A send never hides the composition bar: only that pane's toggle button and the key Escape hide it. Hiding a composition bar removes its images and text, throws away a recording of the voice input that runs for that pane, and closes only that pane's composition bar.
- A click on a picture opens the big view. The big view shows one large picture, with its file name and its position (for example "2 of 3"), a button on each side, and a close button. The key Left and the key Right, and the two buttons, go to the previous and to the next image, and the last image is followed by the first image. The key Escape, the close button, and a click beside the picture close the big view. The big view takes its keys before the terminal and the composition bar.
- A drop never pastes at once: it only adds the images to the composition bar under the pointer.
- The voice input ([issue 662](https://github.com/heidrun-org/heidrun/issues/662)): with the switch "Enable voice input" on, a line under the text input tells why a recording failed. A recording belongs to the composition bar whose push-to-talk button started the recording, and the words go to that composition bar even if focus changes. The rules of the push-to-talk button are in [settings_voice_input.md](../window/settings_voice_input.md).
