This file is a part of the rules of the window of Heidrun Code. The words are defined in [glossary/user_activity.md](../../glossary/user_activity.md).

## The item in the More menu

- The More menu has the item "Statistics", with the icon `bar-chart` and a title (the tooltip). The item is in the first group of the menu, after the item "Mire" and before the first separator line.
- A click on the item opens the Statistics window and closes the More menu.

## The window

- The Statistics window takes the whole screen: it is a Bootstrap full screen window (`dialog-fullscreen`, with `height: 100vh` because the class `dialog-nonmodal` sets its own height), with no margin, no border, and no rounded corner, so there is no padding around it and no dark layer to see. It has a title bar with the title "Statistics", the buttons of its tabs, and a close button, like the other windows built with Bootstrap. The key Escape and the close button close it. A click outside does not close it, because the window has no outside.
- The title bar is thin. It has the title "Statistics" at the left, and at the right the buttons of the tabs, then the close button. The three parts are centered vertically. The padding of the title bar is `--dialog-header-padding: 0.375rem 0.75rem 0.375rem 84px`: the left padding is 84 pixels, as in the top bar, so that the three macOS window buttons (the red, yellow, and green dots), which sit over the top left corner of the full screen window, do not cover the title. The close button is small (the property `isSmall` of `DialogCloseButton`). There is no row of tabs under the title bar, so the tab uses all the height.
- The buttons of the tabs are a Bootstrap button group (`btn-group`) of small outline buttons (`btn btn-sm btn-outline theme-secondary`), with the same look as the radio button groups of the tab, and with no rounded pill. The chosen button has the class `active` and the selected appearance defined by the shared button rules in `styles.css`. The roles follow the page [Tab](https://getbootstrap.com/docs/6.0/components/tab/) of Bootstrap: each tab is a `button` with `role="tab"`, `aria-selected`, and `aria-controls`, the group has `role="tablist"` and an `aria-label`, and each tab pane has `role="tabpanel"` and `aria-labelledby`. Vue switches the tabs, because the application does not load the JavaScript of Bootstrap. The window has two tabs: "User activity" ([statistics_user_activity.md](statistics_user_activity.md)), and "Work of one person" ([statistics_person_work.md](statistics_person_work.md)). The tab "User activity" is selected when the window opens.
- Each button of a tab has an information card tooltip, the component `InformationCardTooltip` (the word is defined in [glossary/status_bar.md](../../glossary/status_bar.md)): a card with the look of the information cards of the Settings window ([settings_information_cards.md](settings_information_cards.md)), so that both cards look the same. Both use the component `InformationCardContent`: a heading with the circled question mark and the name of the tab, then one block for each subject, with a title in a medium weight and a text below. The tab "User activity" has the blocks "What it is" and "How it works". The tab "Work of one person" has the blocks "What it is", "Git history", and "AI cost". The card opens below the button after a delay of 1.5 seconds (1500 milliseconds), when the pointer stays over the button or the button keeps the keyboard focus. A pointer that leaves before the delay ends opens nothing. The card closes at once when the pointer or the keyboard focus leaves, and it never takes the pointer, so a click on the button still switches the tab. The card is a child of the element `body`, so it is never a sibling of a button of the group, and the component draws no element around the button. While it is open, the button has `aria-describedby`. The texts are written as plain text, never as markup, in the translation keys `statisticsModal.userActivityTabWhat`, `userActivityTabHow`, `personWorkTabWhat`, `personWorkTabGitHistory`, and `personWorkTabAiCost`, in every language; the titles of the blocks use `settingsHelp.whatTitle` and `settingsHelp.howTitle`.
- The tab fills the height of the window: the choices are at the top, and the histogram takes the rest of the height, with at least 240 pixels.
- The window follows the rules of [bootstrap_utility_classes.md](../../web_styling/bootstrap_utility_classes.md). The only local rule is the dark layer behind the window, as in the window "Three.js demo"; selected buttons use the shared definition.
- The window reads the user activity data again each time that it opens. It does not read it again while it stays open. The tab "Work of one person" reads the Git history when it is shown for the first time. It updates and reads the stored token usage of the AI cost each time that the developer chooses it, and each time that the chosen workspaces change. It imports the history of a workspace that was never imported only when the developer clicks the button "Import the history". The Git history reads again when the developer chooses another workspace ([statistics_person_work_workspace.md](statistics_person_work_workspace.md)). Each tab first calls its synchronize Tauri command, then its read Tauri command, and the Statistics window gets all its data through the packages of the data layer: the rule, the table of the commands, and the check are in [data_layer_access.md](../../data_layer_access.md).
- While the data is read, the window shows the text "Reading the user activity…" with a busy wheel (the Bootstrap `spinner-border spinner-sm`) before it. The loading message of the source "AI cost" has the busy wheel too, and the source "Git history" shows the stages of the update ([statistics_update_stages.md](statistics_update_stages.md)). When the data cannot be read, it shows the error in a Bootstrap alert, and no chart.
- Every text of the window is in every language, and `pnpm --filter web_frontend check:translations` shows no key of the window as missing.

## The tab "User activity"

- The tab "User activity" holds the histogram of the user activity time, and three choices: the time range, the slot length, and the workspaces. Its rules are in [statistics_user_activity.md](statistics_user_activity.md).

## Where the data comes from

- The histogram reads the user activity records through the data layer, with two Tauri commands of the file `packages/apps/desktop_tauri/src/statistics/user_activity_records.rs`. The command `user_activity_synchronize` copies the new lines of the file `user_activity.jsonl` into the SQLite file of the data layer with the function `refresh_user_activity` of the package `data_layer_user_activity`. The command `user_activity_records_in_range` then reads the records whose active period overlaps the time range with a read-only query. The window asks once, from the start of the oldest slot of any choice of the time range and of the slot length, which is a little less than 7 days before now, and cuts the same records again for each choice. The times of the records that it gives are in UTC.
- The command `user_activity_synchronize` holds the same lock as the write of a record, so it never reads half a line.
- The calculation of the slots, the tab, and the chart are listed in [statistics_user_activity.md](statistics_user_activity.md). Every chart of the window has a chart legend and a chart information card: the rules are in [statistics_charts.md](statistics_charts.md).

## Tests

- `components/MoreMenu.test.ts` tests that the item "Statistics" shows in the first group, and that a click on it opens the Statistics window.
- `components/StatisticsModal.test.ts` tests that the window takes the whole screen and that a press outside does not close it, that the tab list is a button group in the title bar, the thin title bar and its order, the tab that is selected, the second tab, and the information card tooltip of each tab button, with a replacement for Plotly.js.
- `components/InformationCardTooltip.test.ts` tests that the card opens on the pointer and on the keyboard focus only after the delay, opens nothing when the pointer leaves before the delay ends, closes when they leave, has the layout of an information card, writes its texts as text and never as markup, draws no element around the button, puts the card in the element `body`, and gives each card its own identifier. `components/DialogCloseButton.test.ts` tests the small X. `bootstrap_parts.test.ts` tests the Bootstrap parts. The tests of the tab "User activity" are in [statistics_user_activity.md](statistics_user_activity.md).
- The Rust tests of the module `statistics::user_activity_records` test the two commands with a real SQLite file in a temporary folder, also after the file of the records is gone.
