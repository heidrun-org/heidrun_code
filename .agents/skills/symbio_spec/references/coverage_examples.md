# Coverage storage verification examples

## 0. Introduction

### 0.1. Purpose

For contributors exercising [format 3.0.0](format-v3.0.0.md#43-coverage) and its [migration](migration-2-to-3.md) on disposable representative folders. These are verification instructions, not claims that project data has been migrated.

## 1. Retrieval and maintenance

Create examination 1 for permissions on one software revision, recording a known editing failure and explicitly unexamined reading behaviour. Create examination 2 for navigation on another revision. Create examination 3 reporting an editing fix only in one environment, affecting permissions and navigation. Route both topics, retaining the unexamined reading scope and any environments not exercised. Retrieve permissions through its topic summary without opening unrelated examination 2. Open original examinations 1 and 3 before claiming a resolution, and report its limited environment and revision.

Correct examination 1 with correction evidence. Mark affected topics `Needs update` first; keep the latest checkpoint at examination 3 but change examination 1's checksum. Confirm that the old summary fails freshness checks even though the checkpoint is unchanged. Interrupt maintenance before refreshing summaries and confirm that `Needs update` prevents a current-summary claim. Exercise a missing summary, a missing original, an uncertain topic routed through `unclassified`, an unknown date in `undated/`, and a conflicting later observation. Confirm that none becomes silent evidence of completeness or compliance.

## 2. Migration and recovery

Prepare a 2.0.0 folder with nonempty decisions, approvals, a coverage account containing multiple dated examinations, an inseparable undated account, unresolved questions, unexamined scope, known differences and a proposed increment. Include relative evidence links, incoming section links, non-ASCII text, mixed line endings and a source block containing Markdown fences. Run the complete forward procedure, inspect actual records and summary routes, then exact reverse conversion on a separate copy. Compare the whole inventory and bytes, not just the reconstructed coverage text.

Repeat with empty coverage and absent coverage: neither creates a fictional examination. Verify that obsolete paths disappear only after replacements and repository references are checked. Exercise destination collisions, unmappable repository anchors and interruption before version finalization; normal work stays blocked. External links that cannot be updated are reported separately. Add a new examination after migration and confirm exact snapshot restoration refuses to overwrite later work; evaluate section 2.2's semantic reverse conversion or report the specific unrepresentable data. Exercise adoption and 1.0.0 to 2.0.0 before 2.0.0 to 3.0.0 for an unversioned project, verifying each step separately.
